สรุปผล และข้อเสนอแนะ

5.1 สรุปผลการดำเนินงาน
ผู้จัดทำพัฒนาแอปพลิเคชัน Chatshop บนสมาร์ตโฟนด้วย Flutter และพัฒนาระบบบริการหลังบ้านด้วย Laravel 10 ร่วมกับฐานข้อมูล MySQL และ MongoDB เมื่อนำผลมาเทียบกับวัตถุประสงค์ในหัวข้อ 1.2 ได้ผลดังนี้
5.1.1 แอปพลิเคชันรวบรวมข้อความของลูกค้าจากช่องทาง LINE Official Account, Facebook Messenger, Instagram และ WebChat ไว้ในกล่องข้อความเดียว และเจ้าหน้าที่ตอบกลับข้อความ รูปภาพ วิดีโอ และไฟล์เอกสารจากแอปพลิเคชันได้ ซึ่งเป็นไปตามวัตถุประสงค์ข้อ 1.2.1
5.1.2 ระบบส่งเหตุการณ์ผ่าน Laravel Reverb ทำให้แอปพลิเคชันแสดงข้อความใหม่ได้ทันที และส่งการแจ้งเตือนผ่าน Firebase Cloud Messaging เมื่อมีข้อความใหม่หรือแชทค้างตอบเกินกำหนด ซึ่งเป็นไปตามวัตถุประสงค์ข้อ 1.2.2
5.1.3 เจ้าหน้าที่เปลี่ยนโหมดแชทบอท ดูผลวิเคราะห์บทสนทนา และมอบหมาย ปักหมุด จัดเก็บ และติดแท็กบทสนทนาได้จากแอปพลิเคชัน ซึ่งเป็นไปตามวัตถุประสงค์ข้อ 1.2.3
5.1.4 เจ้าหน้าที่จัดการข้อมูลลูกค้าและสินค้า และเปิดคำสั่งซื้อที่ผูกกับบทสนทนาได้จากหน้าต่างสนทนา ซึ่งเป็นไปตามวัตถุประสงค์ข้อ 1.2.4
5.1.5 แอปพลิเคชันเชื่อมต่อระบบหลังบ้านผ่าน REST API ประมาณ 99 เส้นทาง ยืนยันตัวตนด้วยโทเคนของ Laravel Sanctum และตรวจสอบสิทธิ์ตามบทบาทของผู้ใช้ทุกคำขอ ซึ่งเป็นไปตามวัตถุประสงค์ข้อ 1.2.5
5.1.6 ผลการทดสอบด้วยชุดทดสอบอัตโนมัติในกลุ่มที่อยู่ในขอบเขตของโครงงาน ระบบหลังบ้านผ่าน 575 จาก 577 กรณี และแอปพลิเคชันผ่าน 136 จาก 140 กรณี ไม่ผ่าน 1 กรณี และข้าม 3 กรณี รวมกรณีที่ไม่ผ่านทั้งหมด 3 กรณี ซึ่งอยู่ในส่วนการตั้งค่าเท่านั้น
5.1.7 ผลการประเมินความพึงพอใจในการใช้งานแอปพลิเคชันจากกลุ่มผู้ใช้งานและผู้เกี่ยวข้องจำนวน 15 คน พบว่าภาพรวมของระบบได้รับความพึงพอใจอยู่ในระดับดี โดยมีค่าเฉลี่ยรวมเท่ากับ 4.10 และค่าส่วนเบี่ยงเบนมาตรฐานเท่ากับ 0.37 ผ่านเกณฑ์การประเมินที่กำหนดไว้

5.2 อภิปรายผล
จากการพัฒนาและทดสอบระบบ ผู้จัดทำมีข้อสังเกต ดังนี้
5.2.1 การแยกข้อมูลไว้ใน 2 ฐานข้อมูลตามลักษณะของข้อมูลเหมาะกับระบบนี้ ข้อมูลร้านค้า ทีม และคำสั่งซื้อที่ต้องการความถูกต้องอยู่ใน MySQL ส่วนข้อความที่เพิ่มขึ้นตลอดและมีหลายรูปแบบอยู่ใน MongoDB แต่ต้องตรวจรหัสที่อ้างอิงข้ามฐานข้อมูลในโปรแกรมเอง
5.2.2 การตอบกลับ Webhook ทันทีแล้วประมวลผลในคิวงานช่วยให้แพลตฟอร์มไม่ส่ง Webhook ซ้ำ และการบันทึกรหัสข้อความขาเข้าที่ตอบไปแล้วทำให้ลูกค้าไม่ได้รับคำตอบซ้ำ แม้งานเดียวกันจะถูกประมวลผลหลายครั้ง
5.2.3 การแสดงผลการกระทำบนแอปพลิเคชันทันทีก่อนได้รับคำตอบจากเครื่องแม่ข่าย ทำให้ผู้ใช้รู้สึกว่าแอปพลิเคชันตอบสนองเร็ว และย้อนกลับสถานะเดิมได้เมื่อการทำงานไม่สำเร็จ
5.2.4 การรอรวมข้อความ 6 วินาทีก่อนแชทบอทตอบ ทำให้แชทบอทตอบครั้งเดียวโดยเห็นคำถามทั้งหมด และการส่งต่อบทสนทนาให้เจ้าหน้าที่ช่วยลดความเสี่ยงที่แชทบอทจะตอบผิด
5.2.5 การค้นคืนเอกสารความรู้ด้วยการเทียบความคล้ายโคไซน์กับทุกส่วนย่อยทำงานได้ดีกับฐานความรู้ขนาดเล็กของร้านค้า แต่เวลาในการค้นคืนจะเพิ่มขึ้นตามจำนวนส่วนย่อย
5.2.6 การประเมินความพึงพอใจพบว่าด้านประโยชน์และความพึงพอใจในภาพรวมได้รับคะแนนเฉลี่ยสูงสุดที่ 4.16 โดยเฉพาะการช่วยลดภาระและเวลาสลับแอปพลิเคชันเพื่อตอบแชทลูกค้า ซึ่งสะท้อนว่าระบบสามารถช่วยอำนวยความสะดวกในการบริหารจัดการร้านค้าออนไลน์ได้จริง

5.3 ปัญหาและอุปสรรค
5.3.1 Meta อนุญาตให้ส่งข้อความอัตโนมัติได้ภายใน 24 ชั่วโมงหลังข้อความล่าสุดของลูกค้าเท่านั้น ผู้จัดทำจึงต้องให้ระบบส่งซ้ำพร้อมแท็ก HUMAN_AGENT เมื่อเจ้าหน้าที่ตอบเกินกรอบเวลา และงดส่งข้อความอัตโนมัติในกรณีนี้
5.3.2 ไฟล์สื่อจาก LINE ไม่มี URL สาธารณะ ระบบจึงต้องดาวน์โหลดผ่าน API แล้วคัดลอกมาเก็บในระบบก่อนแสดงบนแอปพลิเคชัน
5.3.3 โทเคนของเพจ Facebook หมดอายุหรือถูกยกเลิกได้ทุกเมื่อ ระบบจึงต้องตรวจจับข้อผิดพลาด ปิดการเชื่อมต่อช่องทางนั้น และแจ้งให้ร้านค้าเชื่อมต่อใหม่
5.3.4 การเชื่อมต่อเรียลไทม์หลุดได้เมื่อสัญญาณเครือข่ายไม่เสถียร แอปพลิเคชันจึงต้องดึงรายการบทสนทนาใหม่ทุกครั้งที่เชื่อมต่อกลับมาได้
5.3.5 ยังมีกรณีทดสอบที่ไม่ผ่าน 3 กรณีในส่วนการตั้งค่าธุรกิจและการตั้งค่าแชทบอท ตามหัวข้อ 4.17

5.4 ข้อเสนอแนะและแนวทางในการพัฒนาต่อ
5.4.1 แก้ไขกรณีทดสอบที่ไม่ผ่านทั้ง 3 กรณี และเพิ่มการจำลองการทำงานของแพ็กเกจ flutter_secure_storage ในชุดทดสอบของแอปพลิเคชัน
5.4.2 เพิ่มการบันทึกและส่งข้อความเสียง การส่งสติกเกอร์ และการคัดกรองบทสนทนาตามแท็กหรือสถานะในแอปพลิเคชัน
5.4.3 กำหนดเวลาหมดอายุของคำขอไปยังระบบหลังบ้าน และเก็บข้อมูลบางส่วนไว้บนอุปกรณ์ให้เปิดดูได้ขณะไม่มีสัญญาณเครือข่าย
5.4.4 เตรียมแอปพลิเคชันให้พร้อมเผยแพร่บนระบบปฏิบัติการ iOS
5.4.5 เพิ่มหน้าบรอดแคสต์และหน้าตั้งค่ากฎตอบกลับอัตโนมัติในแอปพลิเคชัน
5.4.6 เมื่อฐานความรู้มีขนาดใหญ่ขึ้น ควรเปลี่ยนไปใช้ดัชนีสำหรับค้นหาเวกเตอร์แทนการเทียบกับทุกส่วนย่อย
5.4.7 ขยายการเชื่อมต่อช่องทางร้านค้าออนไลน์ไปยังแพลตฟอร์มอีคอมเมิร์ซเพิ่มเติม และเพิ่มระบบรายงานยอดขายแบบกราฟิกตามข้อเสนอแนะของผู้ใช้งาน
