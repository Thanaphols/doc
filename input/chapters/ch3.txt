3
วิธีดำเนินงาน

ระบบเว็บของ Chatshop พัฒนาขึ้นเพื่อรวมแชทจากหลายช่องทางไว้ในที่เดียว และช่วยให้ร้านค้าจัดการทีม แชทบอท สินค้า ลูกค้า และคำสั่งซื้อได้จากระบบเดียว บทนี้อธิบายขั้นตอนการดำเนินงานตั้งแต่การวิเคราะห์ปัญหาจนถึงการพัฒนาระบบ โดยมีหัวข้อดังนี้

3.1 กำหนดปัญหาที่เกิดขึ้นกับระบบงาน
ร้านค้าออนไลน์ที่ขายผ่านแชทต้องเปิดแอปพลิเคชันของแต่ละช่องทางแยกกัน เจ้าหน้าที่ต้องสลับหน้าจอไปมา เมื่อมีหลายคนช่วยกันตอบก็ตอบซ้ำกันหรือตกหล่น ไม่มีการแบ่งสิทธิ์ว่าใครเห็นข้อมูลใดได้ คำถามเดิมต้องพิมพ์ตอบซ้ำทุกวัน และการเปิดคำสั่งซื้อยังจดด้วยมือในแชท ผู้จัดทำจึงออกแบบระบบเว็บที่รับข้อความจากทุกช่องทางเข้ามาในกล่องข้อความเดียว พร้อมระบบทีม แชทบอท และระบบจัดการคำสั่งซื้อที่เชื่อมกับหน้าแชท

3.2 การวิเคราะห์ระบบ
ผู้จัดทำวิเคราะห์ระบบจากขั้นตอนการทำงานจริงของร้านค้าที่ขายผ่านแชท แล้วสรุปเป็นผู้ใช้งาน ความต้องการด้านการทำงาน และความต้องการด้านคุณภาพของระบบ ดังนี้
3.2.1 ผู้ใช้งานของระบบ แบ่งออกเป็น 4 กลุ่ม ดังนี้
3.2.1.1 เจ้าของร้าน ผู้สมัครใช้งานระบบ เชื่อมต่อช่องทางแชท เชิญสมาชิกเข้าทีม และกำหนดบทบาทของสมาชิก รวมถึงตั้งค่าร้านค้าและแชทบอท
3.2.1.2 เจ้าหน้าที่ ได้แก่ ผู้จัดการ แอดมิน และพนักงานตอบแชท ใช้งานได้ตามสิทธิ์ของบทบาทที่ได้รับ เช่น ตอบแชท เปิดคำสั่งซื้อ หรือดูรายงาน
3.2.1.3 ลูกค้า ผู้ส่งข้อความหาร้านผ่าน LINE, Facebook Messenger, Instagram หรือ WebChat โดยไม่ต้องเข้าใช้งานระบบโดยตรง
3.2.1.4 แอปพลิเคชันบนสมาร์ตโฟน ซึ่งพัฒนาโดยผู้ร่วมพัฒนา เรียกใช้ข้อมูลผ่าน REST API ของระบบเว็บ โดยใช้ข้อมูลและสิทธิ์การใช้งานชุดเดียวกับหน้าเว็บ
3.2.2 Functional Requirements แบ่งตามส่วนของระบบ ดังนี้
3.2.2.1 ส่วนกล่องข้อความและช่องทาง
1) ระบบต้องเชื่อมต่อ LINE Official Account, Facebook Page, Instagram และ WebChat ได้ โดยร้านค้าหนึ่งแห่งเชื่อมต่อได้หลายช่องทาง
2) ระบบต้องรับข้อความใหม่ผ่าน Webhook และแสดงในกล่องข้อความทันทีโดยไม่ต้องโหลดหน้าใหม่ พร้อมแจ้งจำนวนข้อความที่ยังไม่อ่าน
3) เจ้าหน้าที่ต้องตอบข้อความ สติกเกอร์ รูปภาพ และไฟล์ได้
4) เจ้าหน้าที่ต้องค้นหา ติดแท็ก และมอบหมายบทสนทนาได้
5) ร้านค้าต้องส่งข้อความบรอดแคสต์ตามกลุ่มลูกค้าและตั้งเวลาส่งได้
6) ร้านค้าต้องนำเข้าแชทเก่าจาก Facebook และ Instagram ได้
3.2.2.2 ส่วนทีมและสิทธิ์การใช้งาน
1) ผู้ใช้ต้องเข้าสู่ระบบด้วยอีเมล Facebook หรือ Google ได้
2) เจ้าของร้านต้องเชิญสมาชิกและกำหนดบทบาทของสมาชิกได้
3) เจ้าของร้านต้องสร้างบทบาทใหม่โดยเลือกสิทธิ์การใช้งานเองได้
3.2.2.3 ส่วนแชทบอทและการตอบอัตโนมัติ
1) ร้านค้าต้องเลือกโหมดของแชทบอทได้ 3 โหมด
2) ร้านค้าต้องเพิ่มเอกสารความรู้ให้แชทบอทใช้ตอบคำถามได้
3) แชทบอทต้องส่งต่อบทสนทนาให้เจ้าหน้าที่เมื่อไม่สามารถตอบได้
4) ร้านค้าต้องตั้งกฎตอบกลับอัตโนมัติตามคีย์เวิร์ดได้
3.2.2.4 ส่วนการขายและรายงาน
1) ร้านค้าต้องเพิ่ม แก้ไข และลบข้อมูลสินค้าได้
2) เจ้าหน้าที่ต้องบันทึกข้อมูลลูกค้า และเปิดคำสั่งซื้อจากหน้าแชทได้
3) ระบบต้องแจ้งเตือนเจ้าหน้าที่เมื่อมีแชทค้างตอบนานเกินกำหนด
4) ระบบต้องแสดงรายงาน และส่งออกเป็นไฟล์ CSV ได้
5) ระบบต้องมี REST API สำหรับแอปพลิเคชันบนสมาร์ตโฟน
3.2.3 Non-Functional Requirements เป็นความต้องการด้านคุณภาพของระบบ ดังนี้
3.2.3.1 ด้านประสิทธิภาพ ระบบต้องตอบกลับ Webhook ได้ทันที แล้วจึงประมวลผลข้อความในคิวงานเบื้องหลัง เพื่อไม่ให้แพลตฟอร์มส่ง Webhook ซ้ำ
3.2.3.2 ด้านความปลอดภัย ระบบต้องตรวจลายเซ็นของ Webhook ทุกครั้ง ยืนยันตัวตนก่อนเรียกใช้ API และตรวจสิทธิ์ตามบทบาทก่อนทำงาน
3.2.3.3 ด้านการแยกข้อมูล ข้อมูลของแต่ละร้านค้าต้องแยกออกจากกัน ผู้ใช้เห็นได้เฉพาะข้อมูลของร้านตนเอง แม้ทุกร้านจะใช้ฐานข้อมูลชุดเดียวกัน
3.2.3.4 ด้านความน่าเชื่อถือ ระบบต้องลองส่งงานใหม่เมื่อล้มเหลว และต้องไม่ส่งข้อความเดิมซ้ำให้ลูกค้า แม้งานเดียวกันจะถูกประมวลผลซ้ำหลายครั้ง

3.3 การพัฒนาระบบ
3.3.1 การออกแบบระบบ ระบบแบ่งการทำงานออกเป็น 3 ส่วน ดังนี้
3.3.1.1 Frontend ใช้ Blade สร้างหน้าเว็บทั่วไป และใช้ React สร้างหน้ากล่องข้อความที่ต้องแสดงข้อความใหม่ตลอดเวลาโดยไม่ต้องโหลดหน้าใหม่
3.3.1.2 Backend ใช้ Laravel 10 รับ Webhook ประมวลผลข้อมูล ทำงานเบื้องหลังผ่านคิวงาน และเปิด REST API ให้แอปพลิเคชัน
3.3.1.3 Database ใช้ MySQL เก็บข้อมูลเชิงสัมพันธ์ และใช้ MongoDB เก็บบทสนทนา ข้อความ และฐานความรู้ของแชทบอท

3.4 โครงสร้างระบบเว็บ Chatshop
@fig สถาปัตยกรรมของระบบเว็บ Chatshop

3.4.1 ส่วนหน้าบ้านหรือ Frontend ประกอบด้วยเครื่องมือ ดังนี้
3.4.1.1 Blade ใช้สร้างหน้าเข้าสู่ระบบ หน้าตั้งค่า และหน้าจัดการข้อมูลทั่วไป
3.4.1.2 React ใช้สร้างหน้ากล่องข้อความ โหลดจาก CDN
3.4.1.3 Laravel Echo ใช้รับข้อความใหม่ผ่าน WebSocket
3.4.2 ส่วนหลังบ้านหรือ Backend พัฒนาด้วย Laravel 10 ประกอบด้วยเครื่องมือ ดังนี้
3.4.2.1 Queue และ Scheduler ใช้ประมวลผล Webhook แชทบอท และบรอดแคสต์ในเบื้องหลัง และตรวจแชทที่ค้างตอบทุก 1 นาที

3.7 การเชื่อมต่อกับ LINE Official Account และ Meta
3.7.1 การเชื่อมต่อ LINE Official Account ร้านค้านำ Channel Access Token และ Channel Secret จาก LINE Developers Console มากรอกในระบบ แล้วนำ URL ของ Webhook ที่ระบบสร้างให้ไปตั้งค่าใน LINE Developers Console ระบบใช้ Channel Secret ตรวจลายเซ็นของทุก Webhook ที่ได้รับ จากนั้นส่งข้อความตอบกลับผ่าน Push API โดยใช้ Channel Access Token
3.7.2 การเชื่อมต่อ Facebook Page และ Instagram ร้านค้าเข้าสู่ระบบ Facebook และอนุญาตสิทธิ์จัดการข้อความของเพจผ่าน OAuth จากนั้นเลือกเพจหรือบัญชี Instagram ที่ต้องการเชื่อมต่อ ระบบบันทึก Page Access Token ไว้สำหรับรับส่งข้อความ และตรวจลายเซ็นของ Webhook ด้วย App Secret หาก token หมดอายุ ระบบจะปิดการเชื่อมต่อช่องทางนั้น
3.7.3 การเชื่อมต่อ WebChat ร้านค้าตั้งชื่อ ข้อความต้อนรับ และสีของหน้าต่างแชท แล้วนำโค้ดที่ระบบสร้างให้ไปติดบนเว็บไซต์ของร้าน
